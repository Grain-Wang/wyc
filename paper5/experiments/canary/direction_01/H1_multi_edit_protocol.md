# H1 最小多编辑诊断方案（设计，未批准执行）

状态：**PROPOSED / AWAITING HUMAN APPROVAL / NOT RUN**。
本文件只设计一次有硬预算的诊断；本轮没有实现或运行多编辑 GPU runner。
历史证据固定为 `02bdcd523ed2c2715a396fd624b647ef356a1c87`；
原 H1-small verdict **INCONCLUSIVE** 永久保留。本方案不改其 protocol 或阈值，
也不构成 H2、CET、Jacobian transport、完整 NAS 或论文阶段的授权。

## 1. 问题与停止的价值

研究问题：在同一 block intervention family 下，同时修改4、6、8个block时，
calibration-only加法评分是否开始产生稳定、实际有意义的架构选择损失？

H1-small已显示：在66个双编辑候选中，加法、均值修正、OLS均选中(12,15)，
前三名与validation实测相同。扩大k的理由只是检查组合阶数的边界，不是宣称H1已成功。
若加法在低损伤区仍选对，或二阶/简单直接评估已解决问题，应停止复杂方法投入。
高损伤关键层引起的模型崩坏不能单独支持NAS研究价值。

## 2. 固定模型、干预与数据

- 模型仍为 `Qwen/Qwen2.5-1.5B`，revision
  `8faed761d45a263340a0528343f099c05c9a4323`，bf16、eval、eager attention；
  同一tokenizer、512输入token（511预测labels）、batch=1、无训练/蒸馏。
- 仍使用 `whole_transformer_block_skip`；零起点可编辑位置仅为
  `[1,3,6,8,10,12,15,17,19,21,24,26]`。
  k=4/6/8占28个block的14.3%/21.4%/28.6%，但这只是干预比例。
  冻结实现是forward hook替换block输出，原block仍执行；
  不能把它的wall time或参数量当成结构压缩的真实收益。
- 输入train/valid本地优先，SHA256须分别为
  `9e9fa1ad55b1c2c95b08e37dd8e653f638fac2c6de904b79e813611eefbc985f`、
  `f0737ed31fc1329026e95cb8b98e19c2a182c39c240ab909dc31abf2f8af58e8`。
- Calibration C：原96个train窗口及其原3×32 disjoint shards，完全复用
  归档source indices。parent、12 singles、66 pairs的逐窗口calibration NLL复用。
  不重新采样C，不读取WikiText test。
- 旧64个validation窗口称为V_old：仅用于历史k=2描述，不进入新的评分、候选构造
  或确认判定。不把同一64窗再bootstrap称为新证据。

### 新的内部确认窗口 V_new（仅在获批后准备）

对同一冻结valid文本、tokenizer执行原非重叠512-token chunk划分。
排除V_old所有source_window_index，以及这些索引的±1邻居；
对余下合法完整chunk索引j，按
`SHA256(UTF8("20260922:holdout:" + str(j)))` 升序排序、j打破hash并列，取前64。
记录完整源索引、文本SHA、tokenizer revision和最终token tensor SHA，**在任何新模型
前向之前冻结**。合格窗少于64即停止请求新方案，不能自动减少窗数、更换语料或用test补足。
V_new前32/后32（按上述hash顺序）是预定义的两个确认切片，不重新随机找有利拆分。

本轮不能从归档中获得剩余valid完整chunk总数，因而不伪造64个实际索引；
以上确定性算法和排除规则是已固定的抽样合同，未来预检生成索引后须写入运行manifest。
新窗口与旧窗口不重叠及相邻排除减少直接复用，但同语料/同文档仍可能相关。
方案与阈值由已观察过V_old的人设计，因此V_new只是**后续锁定方案的内部确认**，
不是独立最终test或跨语料泛化证据。若V_new已被其他实验观察过，应停止，不能声称盲确认。

## 3. 固定候选生成与分层

k=2复用既有66 pairs，仅提供历史参照，不新增k=2前向，不与V_new的k=4/6/8
混合做趋势显著性检验。k=4/6/8各固定30个不同候选，合计90个：

- `global`：在该k的12位置完整组合集合中，固定抽取15个；
- `low`：按calibration additive分数定义的低损伤候选池，再抽取15个。

完整组合数分别为495、924、495。这里的“全空间”只指这12个位置的组合，
不是28层全部子集、任意block替代库或完整NAS空间。

精确生成规则（仅依赖归档calibration singles）：

1. 每个tuple内部升序。令s(A)=sum Δ_i,C；按(s(A), tuple)排序，
   取最前ceil(N/4)作为低损伤池，大小分别为124、231、124。
2. seed=`20260920`；global按
   `SHA256(UTF8("20260920:" + str(k) + ":global:" + comma_join(A)))`
   升序取前15，hash并列按tuple。
3. 从低损伤池去掉已经选中的global候选；按对应
   `"20260920:" + str(k) + ":low:" + comma_join(A)`的hash升序取15。
   因此low是“条件于global不重复”的低分池样本，不宣称它是完整低分池无条件随机样本。
4. 以附录的90个具体tuple为执行清单；候选清单不能按validation、二阶预测好坏、
   层距离或运行后损失重挑，也不强行加入某个预测胜者。
   三个k使用同一规则，不搜索不同seed。

每个k内，global15与low15**分别报告**；low是决策相关性主面板，global是宽范围压力诊断。
每个k的30合并结果只作次要描述，不跨k汇总相关性或选一个最有利k。
低损伤池由加法定义会偏向加法可行区，这种选择偏置必须披露；它故意测试
竞争性候选附近是否仍有问题，不能据此证明所有候选空间都不存在交互。

候选生成在CPU复核脚本的 `candidate_manifest` 中，不是GPU runner。
规范manifest（包含每k的universe_count、low_pool_count、两份有序15-tuple列表）
以JSON `sort_keys=True, separators=(",",":")` UTF-8编码，其SHA256固定为：
`7c40b1a1963d76e99144d7b27608fbfc6e68f1831e244f332e217a9c704021b9`。

## 4. 评分和真正可执行的选择流程

所有评分参数、特征、短名单和真实复评选择都只用C。
在获得任何新V_new标签前冻结每个(k,stratum)的预测顺序与策略选中者：

1. **加法**：s1(A)=sum(i in A) Δ_i,C。
2. **完整二阶**：
   s2(A)=sum(i in A) Δ_i,C + sum(i<j in A) I_ij,C。
   I_ij,C=L_C(ij)−L_C(i)−L_C(j)+L_C(parent)，只用已测calibration pairs。
   每个pair恰计一次，不clamp、不按V_old/V_new拟合权重。
   k=2时s2恰等于calibration实测pair Δ；这是代数恒等与已测标签复用，
   不能算对未知architecture的预测成功。
3. **直接评估参照**：每个15候选面板按
   `SHA256(UTF8("20260921:" + str(k) + ":" + stratum + ":" + comma_join(A)))`
   固定均匀伪随机顺序；用前b个候选的C实测NLL选最小者。
   b固定为1、3、5、10、11、15，用前缀嵌套，不尝试多个随机顺序取最好。
4. 额外的简单补救：对s1、s2各自预测前5个，用C真实复评并选最小者。
   这是shortlist reranking，不用V_new重新挑胜者。
5. 直接评估全部15个的C胜者a_C作为calibration固定参照。
   计算它需要付出全候选C测量成本，它不是免费oracle或无预算限制的竞争方法。

同一(k,stratum)中所有并列按tuple顺序处理。90个新候选的C标签可以一次性测量，
但策略分析必须模拟各预算允许看到的候选前缀；不把未查询标签偷偷供给拟合或选择。
s1/s2排序在取得这些新候选C标签之前就冻结。
不拟合多编辑回归器、不新增transport、不依据效果增加三阶项。

## 5. 主要指标、实际意义与不确定性

每个(k,stratum)单独报告所选tuple、预测Δ、C实测Δ、V_new实测Δ；
baseline的MAE、RMSE、Pearson、Spearman、Kendall、Top-1/3/5/10/15集合重合；
shortlist内V_new事后最佳（仅诊断）与C复评后选择的V_new效果分别列出。
不能混合不同k或把“事后shortlist最佳”写成部署收益。

### 主要可确认比较

a_C在C上预先固定，a_add由s1固定。定义
**G_add = L_Vnew(a_add) − L_Vnew(a_C)**。
这是“加法选择相对一个calibration可确定参照的实际损失”，不使用V_new选择参照。
G可以为负，不截断；a_C的昂贵测量成本单独披露。
所有其他策略同样报告G_b=L_Vnew(a_b)−L_Vnew(a_C)。

同时报告用户关心的**simple regret**
R_b=Δ_Vnew(a_b)−min(A in 同一15候选面板) Δ_Vnew(A)。
V_new实测最优仅是有限面板的事后参照，不是全空间真最优。
R非负；重采样中重新取min会带来最小值选择效应，因此R区间只是有限面板
bootstrap诊断，不能替代固定a_C的主要配对比较。

预先定义实际有意义损失 **ε=0.02 nats/token**，约等于同一token评价下
**2.02%的perplexity比值**。这是本次新诊断的工程决策门槛，
不是普适用户体验阈值，也不追溯修改旧H1的0.10/0.90/0.75条件。
差值小于ε不包装成值得复杂算法投入的收益。

实用性检查：一个面板至少有3个候选满足Δ_Vnew≤0.30 NLL，
且a_C也满足此条件，才可支持“可用候选间选择损失”的继续条件。
0.30约为parent perplexity的1.35倍，是宽松的诊断边界而非部署质量认证。
不把不满足者从原统计中删除；仍完整报告15/30个结果，只将该k标为
“damage-dominated / 不足以支持实际NAS价值”。

### 重采样与稳定性

20,000次paired V_new-window bootstrap，seed=`20260923`。
每次同一64窗索引向量作用于所有90候选及parent，保留跨architecture和跨k依赖；
候选清单与C选出的策略保持固定，不bootstrap候选或共享层的pair。
主low面板的三个G_add同时做Bonferroni校正：
每k采用0.833333%/99.166667% percentile interval（98.333333%），
名义family error 0.05；同时给出未校正95%区间。
这是window bootstrap近似，不保证文档相关性下精确覆盖。

G_add在两个预定义32窗V_new切片也必须分别>0.02，才能称“稳定、实际相关”。
用原C的三个32窗shards分别重算single/pair特征和s1/s2选择（候选不重抽），
报告其各自在V_new上的G/R；继续条件要求三个shard的加法G同号且均>0.02。
这是calibration敏感性诊断，不额外新增随机模型run。

其他G_b、R、排名和误差区间均为次要描述；涉及“简单方法已经解决”的停止判断，
要求该方法G_b和R_b的95%上界均≤0.02。单个不显著差异不能证明等效。

### 方法使用的信息成本

用“一个architecture在固定96个C窗口上的实测”作为一个calibration评价单位；
所有策略共用一个parent，跨k共享的single/pair成本只计算一次。
低损伤候选池的构造也依赖12个calibration singles，因此候选构造的13单位
是所有策略共同承担的冷启动成本；直接评估不能免费获得这份信息：

- 加法冷启动：parent+12 singles = **13单位**（1,248 windows）。
- 二阶冷启动：parent+12 singles+66 pairs = **79单位**（7,584 windows）。
  比加法多 **66单位 / 6,336 windows / 3,244,032输入tokens**；
  既有归档让本次新增成本为0，但不能写成算法信息免费。
- 原H1还测过同样79个architecture的64个V_old窗，共12,640历史windows；
  方法拟合只用其中7,584个C窗，全部历史运行成本另外列账。
- 新诊断测全90个C候选是**审计代价**（8,640 windows），而非所有策略可免费读取的标签；
  新V_new标签也只供评价，不能计入模型选择输入。

六个面板（3个k×2个strata）同时运行时，普通方法与直接评估的冷启动预算配对如下：

| 策略 | Calibration单位 | 同预算或更低预算的直接评估 |
| --- | ---: | --- |
| 加法Top-1 | 13 | 仅候选构造，未余真实候选查询预算；固定随机首项可作零查询参照 |
| 加法Top-5真实复评 | 43 | 每面板前5个，13+6×5=43 |
| 二阶Top-1 | 79 | 每面板前11个，13+6×11=79 |

若将固定候选清单当作外部已给输入，直接评估全部候选本身需要parent+90=91单位，
但这只是条件成本；包含本方案低损伤池构造的主冷启动总账必须报103，不能只报91。
已有96窗parent与single/pair数据的复用，在冷启动及沉没成本视图中须分别标注。

另给“历史setup已沉没”的增量视图：在每面板5次新候选评价预算下，

必须与冷启动表同时出现，不能只展示对二阶有利的摊销视图。
报告实际wall time、architecture-windows和峰值显存；不把某k的少量候选优势
外推为大NAS空间效率。这里的干预hook不真正省略block计算，真实速度收益未测。

## 7. 预定继续、停止或不确定条件

判定只依据预先指定的**low主面板**；global大误差是压力诊断。
每个k先检查完整性/实用性，再检查G_add的校正区间、两个V_new切片和三个C-shard选择稳定性。

- **可请求H2可行性审核（不是执行授权）**：至少2个k通过实用性检查，
  G_add的校正下界>0.02，两个V_new切片与三个C-shard选择也满足上述稳定性；
  并且在至少相同两个k上，冷启动成本不超过79单位的简单策略
  （加法Top-5复评、二阶Top-1、直接5/11次每面板评估）的G的95%下界
  仍均>0.02。只有“不满足已解决标准”不够，区间不确定就归入仍不确定。
  同时完整C参照自身的R上界须≤0.02，以免把calibration→V_new漂移误认作加法组合失败。
  即使符合，也只支持提交一个针对**未解决组合选择损失**的H2假设；
  不能推断Jacobian transport会有效。新H2须单独说明为何预计在不超过79单位内
  优于二阶与直接评估；完整直接评估只需103单位，只有24单位的预算差，
  不能隐去这个很强的反方理由。二阶Top-5的109单位对照只作为高预算描述，
  其103单位完整直接参照不纳入这个79单位继续门槛，但必须完整报告。
  新H2还须说明为何预计比简单二阶/直接评估更省，
  并获人工授权。单凭“次要baseline不显著”不能认定它们失败或证明CET价值。
- **停止此方向的复杂方法投入**：全部可用low面板的加法G与R上界≤0.02；
  或原本有material信号的面板都被上述简单策略以匹配预算解决；
  或信号只来自高损伤关键层/不可用模型。后者表示当前干预面板没有展示实用问题，
  不等于证明所有多编辑架构都可加。
- **仍不确定**：只有一个k满足、CI跨过门槛、calibration-shard/确认切片不稳定、
  V_new参照存在明显跨split漂移、只有排名误差而没有实质G，
  或简单参照的效果不确定。保持待审状态，**不增加k、换seed/候选、放宽ε或自动进入H2**。
- 不满足完整性或总预算的运行没有科学通过/失败判定，只报告未完成。

这些规则有意保守：目前90候选规模下直接评估非常有竞争力；
本诊断不能承诺形成算法机会。它的价值也包括给出足够的停止理由。
没有任何条件允许本轮启动实验，最终范围由用户确认。
