## 唯一修订

审计范围为 paper5 已记录实验对同一 valid 文本的使用，不要求证明公开语料从未用于
基础模型预训练。本确认集仅称为 **项目内隔离后的内部确认集**，不是跨文档独立测试
或最终无污染 benchmark。未记录的实验以及基础模型训练语料不在可核验范围内。

1. 使用冻结 valid SHA、tokenizer 和无 special token 的整段 UTF-8 文本分词，按
   非重叠 512-token 完整 chunk 定义确认候选；末尾不足 512 的部分不用。
2. 保留 V_old 的全部 64 窗及各自 ±1 邻居排除。
3. 将已核验 smoke、sanity、H1-small 窗口转为半开 source-token 范围。
   仅在源文本、分词设置及完整 token 流经核验一致时共用坐标。
   不同长度的窗口编号不能直接比较；不同 tokenizer/设置必须先证明坐标一致
   或建立可核验的 source-text 映射，不能默认为相同；本实现遇不兼容坐标立即停止。
4. 排除任何与历史范围有正长度交集的 512-token 窗，再排除这些窗的 ±1 邻居。
   不对邻居递归扩张。所有排除原因写入随附 JSON。
5. 对剩余合法 j 按 `SHA256(UTF8("20260922:holdout:" + str(j)))` 升序、j 打破并列，
   一次取前 64；不改 seed，不读取模型损失筛窗。前 32/后 32 仍是预定义确认切片。
6. 若不足 64 窗或工程预检失败，停止并保留日志；不减量、不改用 test、不换语料。
7. 若在修订前已产生或查看过新多编辑测量，停止，不自动重选。

## 冻结内容与执行顺序

`H1_multi_edit_isolation_v2.json` 在新模型前向前冻结：原 V_new、V_old、全部历史
曝光范围与原因、V2 的有序 64 窗、源数据 SHA、两个 tokenizer 的文件 SHA、完整
valid token 流 SHA、原/V2 确认 tensor SHA（按有序 `<i8` bytes）和候选 manifest SHA。
`prepare` 在已提交的精确代码上重算、逐项比较，再把 C/V2 最终 tensor SHA、协议 SHA、
隔离记录 SHA、执行代码完整 SHA 写入新输出的 config/manifest/state，随后才允许加载模型。
`evaluate` 再核验隔离版本、记录、确认 indices 和 token tensor；旧结果不作为写入目标。
新输出仍为原授权的 `H1_multi_edit/`，内部显式携带 V2 版本，不覆盖 `H1_small/`。

保留既有 runner、测试和执行说明并增量修订；初始草稿哈希随隔离记录保存。
先自检、提交代码，再以既有 SSH/bundle 路径同步精确提交到 A800。单次后台运行沿用
7,200 秒模型预算（含 imports/loading/checks）、1,800 秒 CPU 分析预算、动态单卡及
至少 8,192 MiB 空闲显存保护；不抢占其他进程，不自动重试。
不进入 H2、不新增候选、不扩大实验；任何不完整结果只报工程未完成。
